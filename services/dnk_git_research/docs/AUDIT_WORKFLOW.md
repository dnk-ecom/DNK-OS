# Воркфлоу аудиту репозиторіїв

## Принцип
Якість аудиту не повинна залежати від сили моделі. Усе, що має правильну відповідь, робить система. Модель робить лише те,
що потребує судження, малими кроками, і не рухається далі без перевірки.

## Розподіл ролей
| Система (детерміновано) | Агент (судження) |
|---|---|
| тріаж: каталог, оцінка бібліотеки, ліцензія → дозволені дії, gate | identity: що це насправді, вид, якість |
| закріплення коміту, вибір і читання файлів (`--focus`) | claims: заява README проти коду |
| нумерація рядків у кожному файлі | mechanics: що можна відтворити, де, як |
| автопідказки: збіги слів, ризики (значення секретів не копіюються) | risks: розбір кожної підказки |
| перевірка цитат (sha, файл прочитано, рядки існують), ліцензія vs дія, модуль DNK існує | verdict: KEEP/WATCH/REMOVE, що брати |
| звірка з реєстром (`ledger fit`), оцінка A/B/C, звіт, чернетка реєстру | |

## Цикл кроку
`next` (самодостатній промпт з потрібними доказами й точною формою JSON) → відповідь → `submit` (толерантний розбір JSON, структура,
повнота заяв, обробка кожної ризик-підказки, цитати, ліцензія) → або прийнято, або короткий точний список помилок
для виправлення. Три відхилення поспіль: крок іде людині. Підробки не існує: пропуск `skip` фіксується в звіті й знижує оцінку.

## Чому це працює зі слабкою моделлю
- Малий крок і лише потрібні докази в промпті; бюджет символів керується `--budget`.
- Рядки вже пронумеровані: модель не рахує.
- Форма відповіді показана буквально; відповідь із текстом навколо JSON і зайвими комами приймається.
- Помилки конкретні («рядки 2-999 поза файлом, у ньому 40»), а не «спробуй ще».
- Стан у файлах `runs/<run>/`: інший агент або інша модель підхоплює запуск з будь-якого кроку.

## Оцінка якості аудиту
A: усі кроки пройшли, ≤3 виправлень, прочитано ≥50% бюджету файлів. B: пропущено крок, або багато виправлень, або мало прочитано.
C: ≥2 кроки пропущено/передано людині, або остаточна перевірка знайшла проблеми. Оцінка описує процес доказів, а не цінність репозиторію.

## Результати запуску
`audit.md` (звіт людині), `dossier.json` (машинне досьє), `ledger_draft.yaml` (донор і механіки зі статусом candidate;
`audit promote --confirm` додає його в реєстр лише після перевірки реєстру).

## Межі
Система гарантує, що цитати правдиві й ліцензія дотримана; вона не гарантує, що судження моделі розумне (наприклад, що механіка
справді цінна). Для цього є вердикт людини на статусі candidate. Мовою промптів є українська, слабкі моделі можуть гірше слідувати їй.
