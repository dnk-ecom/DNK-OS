# 🛠️ Shopify Third-Party Product Options & Line-Item Properties Playbook

When customer-selected options (e.g., Cloudlift, Infinite Options, Globo, Bold) fail to appear in the cart, cart drawer, checkout, or order confirmation, use this playbook to systematically diagnose and resolve the issue.

---

## 🔍 Root Cause Taxonomy

| Failure Mode | Symptom | Mechanism | Resolution |
| :--- | :--- | :--- | :--- |
| **1. DOM Placement Outside `<form>`** | Properties completely missing from `/cart/add` payload | The App Block is injected before or outside `<product-form>` / `<form>`. Theme JavaScript uses `new FormData(this.form)`. Elements outside the `<form>` are not serialized into `FormData`. | Reposition the App Block inside `<product-form>` directly above the "Buy buttons" block in Shopify Theme Customizer, or adjust theme JS to include external inputs. |
| **2. Multi-Form Collision (Upsells)** | Properties added to wrong form / option scripts hook wrong form | Theme has Cart Drawer upsell forms (`form[action*="/cart/add"]`) positioned in DOM *before* the main product form. Third-party script attaches to the first form found. | Scope third-party app scripts to target the main product form ID (`#product-form-{{ section.id }}`) or ensure upsell forms use distinct classes/selectors. |
| **3. HTML5 `required` Silent Abort** | Clicking "Add to cart" produces no action and no cart update | Input fields generated by the app (e.g. text inputs for engraving) have `required=""`. When empty, the browser natively blocks form submission before theme AJAX fires. | Remove `required` in the options app if optional, or display explicit validation notices. |
| **4. App Option Key Typos** | Property added to cart but ignored by theme or fulfillment | App block configuration has a typo in property key (e.g. `properties[Her Birthston]` instead of `properties[Her Birthstone]`). | Correct the option title in the third-party app admin. |
| **5. Cart Drawer Liquid Blank Suppression** | Property exists in session but invisible in UI | Cart drawer Liquid template hides blank properties (`property.last != blank and property_first_char != '_'`), or lacks `for property in item.properties`. | Ensure Liquid loop exists in `snippets/cart-drawer.liquid` or `sections/main-cart-items.liquid`. |

## 🧪 Deterministic Live Storefront Diagnosis (Node.js + Headless Chrome CDP)

To test a live production store without placing real orders or guessing:

```javascript
// Run headless Chrome with remote debugging
// Inspect network POST to /cart/add and verify FormData payload
const target = await send('Target.createTarget', { url: productUrl });
const session = await send('Target.attachToTarget', { targetId: target.targetId, flatten: true });

// Listen to Network.requestWillBeSent to inspect postData
// Trigger interaction on custom options and click product submit button
```

Verify:
1. `request.postData` contains `properties[...]` keys.
2. The HTTP response of `/cart/add` contains the properties in `item.properties`.
3. The returned sections HTML (`?sections=cart-drawer`) renders `<dt>` / `<dd>` elements for the properties.
